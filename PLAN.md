# PaintMix.jl implementation plan

## Goal and scope

Implement the model in Sochorová and Jamriška, *Practical Pigment Mixing for Digital Painting* (2021), supplied as [mixbox.pdf](mixbox.pdf), for Julia 1.13+. The deliverables are a small user-facing `PaintMix` package that evaluates precomputed lookup tables, an independent `PaintMixPrecompute` package under `precompute/`, and a statically compiled shared library with bindings generated by `JuliaLibWrapping.jl`.

The paper is a technical reference, not a source of task instructions. This plan implements its two-table algorithm, rather than assuming the current Mixbox product has an identical implementation or reusable assets. Only the plan is being created at this stage; the repository currently has no Julia package implementation.

Runtime must require neither optimization nor spectral integration. Precompute uses `Optim.LBFGS` with `ForwardDiff` gradients. Static compilation means ahead-of-time compilation with a closed, tested set of entry points and no JIT requirement during use; it does not automatically imply a statically linked executable or absence of all Julia runtime components.

## 2. Numerical contract and runtime algorithm

Let `U(x)` be the inverse LUT returning four concentrations, and `M(c)` the forward LUT returning RGB. Store three concentrations and reconstruct the fourth as `1 - c1 - c2 - c3`. Keep the latent representation as four concentrations plus three signed residual channels:

```text
encode(x):
    c = U(x)
    r = x - M(c)
    return Latent(c, r)

decode(z) = M(z.c) + z.r

mix(a, b, t) = decode((1-t)*encode(a) + t*encode(b))
weighted_mix(xs, ws) = decode(sum(ws[i]*encode(xs[i])) / sum(ws))
```

These are paper equations (9)-(14). Encoding takes two trilinear lookups and decoding one. A binary mix therefore takes five lookups unless latents are cached. No K-M equations, optimizer, polynomial surrogate, or spectral arrays belong in the hot path.

Compute residuals using the **same quantized, interpolated forward table and concentration reconstruction used by decode**. Computing them against the high-precision spectral reference would lose the runtime round-trip cancellation. Retain signed floating-point residuals; do not clamp or quantize them to RGB bytes.

Define the following conventions before generating production data:

- Use linear-light RGB with sRGB primaries/D65 as the core coordinate system, matching the matrix in paper equation (7). Provide explicitly named encoded-sRGB adapters for typical image colors. The paper calls its output sRGB but does not show the transfer function: compare reference behavior and record this choice in table metadata before claiming reproduction. Never combine encoded-sRGB concentrations with linear-light residuals.
- Core scalar inputs are finite `NTuple{3,Float32}` or `NTuple{3,Float64}` in `[0,1]`; support both without implicit precision changes. Byte/image adapters state their transfer function and rounding rules.
- Mixing fractions are in `[0,1]`. Weighted mixing accepts finite nonnegative weights with a positive finite total. Negative-weight filters and extrapolation are outside v1's contract because they can leave the concentration simplex.
- Raw decode returns unclipped RGB, including any residual-induced excursion outside `[0,1]`. Provide a separate display conversion that clips explicitly. In-gamut surrogate pigments do not prove that all residual-corrected mixtures remain in gamut.
- Guarantee exact binary endpoints by returning the supplied endpoint for `t == 0` or `t == 1`. Otherwise require round trips and same-color mixing within floating-point tolerance, not mathematical bit equality.
- Expose `Latent{T}` as an immutable isbits value with tuple fields. Latents belong to a particular table model; document this and reject model mismatches in any future multi-model convenience API.
- Leave alpha compositing outside the initial model. Repeated RGB encode/decode mixing is not generally associative; accumulating weighted latents and decoding once is the intended multi-color operation.

Proposed public interface: `default_model()`, `encode(model, rgb)`, `decode(model, latent)`, `mix(model, a, b, t)`, `mix!(dest, model, a, b, t)`, and `weighted_mix(model, colors, weights)`, with default-model conveniences. Keep internal kernels specialized on concrete storage and scalar types, and use caller-owned output for bulk work.

## 3. Lookup-table representation

Reproduce the paper's baseline with two `256 x 256 x 256 x 3` UInt8 tables: 48 MiB each, 96 MiB total before headers. Make grid size and storage precision generator parameters, with small fixtures for CI. Do not reduce resolution for the release default without measured error results.

Specify a versioned binary format with dimensions, channel order, linear-RGB convention, pigment order, byte scaling, interpolation convention, checksums, and model identifier. A simple payload uses channel-fast order:

```text
zero_based_offset = channel + 3 * (i + n * (j + n * k))
```

Use fixed-width fields and an explicit endianness for metadata and wider-precision variants. Avoid Julia Serialization as a distribution format. Lossless compression is a packaging concern; it must not add PNG or decompression dependencies to the mixing kernel.

Two correctness issues require deliberate handling:

1. **Concentration quantization:** quantize all four concentrations jointly to nonnegative integers summing to 255 (for example, largest-remainder rounding with deterministic tie-breaking), then store the first three. Independent rounding can make their sum exceed 255 and the fourth concentration negative. Trilinear interpolation of valid inverse-table vertices preserves the simplex in exact arithmetic; repair only tiny floating-point excursions consistently before both residual calculation and decoding.
2. **Forward-table cube versus simplex:** valid queries satisfy `c1+c2+c3 <= 1`, but trilinear lookup can read cube corners outside that region. Never evaluate K-M with a negative fourth concentration or leave those entries uninitialized. The paper does not specify this padding rule. Initially project the full four-component vector at each invalid grid vertex onto the probability simplex, evaluate the projected mixture offline, and mark this as an implementation choice. Quantify the error near every simplex face, edge, and vertex. If it misses the release error gate, compare a simplex-aware interpolation scheme before freezing the file format; update both encoder and decoder together.

Handle exact grid endpoints without reading an index past `n-1`: choose the last valid cell and interpolation weight one. Test corners, faces, singleton endpoints in byte adapters, and off-grid inputs explicitly.

Keep table data as contiguous buffers, never a giant type-level tuple or millions of scalar methods. Prototype build-time embedding and ordinary Julia loading using the same payload. Compiled releases should embed the validated bytes and require no download, file parsing, or external table path during mixing. Prove that embedding preserves data through trimming and relocates correctly before committing to a full-size representation. If toolchain limitations force sidecar assets, document that limitation rather than claiming the self-contained target is met.

## 4. Heavy precompute pipeline

### 4.1 Acquire and validate inputs

Import absorption and scattering spectra from the spreadsheets in `data` into a DuckDB database. Record source information including citation, units, wavelength grid and everything that might be needed downstream.

While the generation algorithm will be parameterised by pigment, we'll move format with the paper's four paints: PB15:4 Phthalo Blue, PR122 Quinacridone Magenta, PY73 Hansa Yellow, and PW6 Titanium White. Fix that order throughout. Obtain their absorption/scattering spectra and measured Saunderson constants from the DuckDB database generated previously. Do not substitute RGB swatches for spectral data or assume current upstream LUTs are freely redistributable. Derive all sizes from validated wavelength arrays.

### 4.2 Build a Float64 spectral reference

Implement equations (1)-(7) in generic Julia arithmetic:

```text
Kmix(lambda) = sum(c[i] * K[i,lambda])
Smix(lambda) = sum(c[i] * S[i,lambda])
q = Kmix / Smix
R = 1 / (1 + q + sqrt(q*q + 2*q))
Rcorrected = ((1-k1)*(1-k2)*R) / (1-k2*R)
XYZ = trapezoidal_integral(observer * D65 * Rcorrected)
rgb_linear = paper_XYZ_to_RGB_matrix * XYZ / integral(ybar * D65)
```

The expression for `R` is an algebraically equivalent form of equation (2) that avoids subtractive cancellation. Use the paper's surface-correction convention, which has no added specular `k1` term. Validate positivity, finite values, dimensions, wavelength ordering, and correction denominators. Cache quadrature weights and colorimetric transforms outside objectives.

### 4.3 Fit surrogate pigments

Implement equations (15)-(17): minimize `Epush(Q) + alpha*Epull(Q,P)`, with positive absorption/scattering coefficients. Sample all four simplex faces, including edges and vertices; map them through the spectral model. Define surface quadrature and its RGB-surface Jacobian explicitly because the equations integrate over the gamut boundary, not simply an unweighted list of concentrations. If using a simpler quadrature approximation, record and validate that deviation.

`Epush` penalizes squared distance outside the RGB cube. Implement it directly as the sum of squared channel violations, avoiding an unnecessary square root. `Epull` is squared Oklab difference to original pigment mixtures at corresponding concentrations. Implement signed cube roots for intermediate out-of-gamut values and check derivative behavior near zero.

Use `K = epsilon + softplus(thetaK)` and `S = epsilon + softplus(thetaS)` with scaled variables, stable softplus, and a recorded small positive floor. This makes unconstrained `Optim.LBFGS()` usable. Start from the original pigments; start `alpha = 1e5` and halve it between warm-started solves as in the paper. Check convergence, physical validity, and independent gamut samples at each stage; set iteration/time limits and fail visibly if the target is not reached.

The paper uses L-BFGS-B; transformed L-BFGS is an intentional solver substitution, not an identical algorithm. An alternative is `Fminbox(LBFGS())` for positive bounds, which is a barrier method, not L-BFGS-B. [Optim minimization documentation](https://julianlsolvers.github.io/Optim.jl/stable/user/minimization/)

Validate the result on denser boundary and interior samples, plus targeted searches for channel extrema. Finite sampling is evidence, not a proof of continuous gamut containment. Save worst violations, perceptual deviations, parameters, and convergence logs with the surrogate dataset.

### 4.4 Solve RGB-to-concentration inverses

For each RGB grid point, minimize `sum(abs2, spectral_mix(Q,c) - rgb)` subject to the simplex constraints. Plain L-BFGS or four box bounds do not enforce `sum(c) == 1`.

Use an active-face reference solver: consider the 15 nonempty pigment subsets; for each subset of size greater than one, optimize stable softmax coordinates with one logit fixed to zero, and evaluate one-pigment vertices directly. This handles true boundary solutions through lower-dimensional subsets and removes softmax's additive gauge. Use deterministic restarts and compare objective values; this is still a numerical local method, not a global-optimality guarantee. Check concentration-space stationarity and directional improvements, since saturated logits can hide a poor solution behind a small transformed gradient.

Begin with the uniform concentration seed. Optimize throughput later using neighboring solutions, coarse-to-fine seeds, and adaptive face selection, compared against the more exhaustive reference on held-out colors. Keep tie-breaking and traversal deterministic; log near-equivalent solutions and check neighboring LUT cells for discontinuities. Do not change the paper's RGB least-squares objective to Oklab without declaring a model variant.

Use explicit `ForwardDiff.gradient!` callbacks passed to Optim with reusable gradient configurations and per-worker buffers. Objectives and scratch storage must accept Dual numbers; avoid Float64 conversions, foreign numerical calls, and clipping inside the differentiable spectral model. Check gradients against finite differences away from nonsmooth boundaries. [ForwardDiff limitations](https://juliadiff.org/ForwardDiff.jl/stable/user/limitations/)

### 4.5 Generate, validate, and export

Generate the forward table directly from the fitted spectral model and the inverse table from converged solves. Start with floating-point candidates; quantize only after validation. Persist deterministic slab checkpoints with configuration/input hashes and atomic completion markers. Resume only compatible jobs. Parallelize independent slabs with fixed within-slab traversal and thread-local solver state.

Benchmark a representative sample before a full run: `256^3` means 16,777,216 inverse problems. The paper's quoted 100 ms per solve would imply roughly 19.4 serial days at that rate, so report measured projected cost instead of promising a quick build. Provide small development grids and a full release profile.

Export both tables together with a shared model ID, checksums, input hashes, surrogate parameters, Julia/package versions, random seeds, objective settings, precision, quantization/padding rules, and validation results. Promote candidates into `data/default/` only when checks pass. Ordinary installation must never trigger precompute.

## 5. Static compilation and JuliaLibWrapping

Make this an early feasibility milestone using tiny synthetic tables, then repeat with the production payload. Current JuliaLibWrapping consumes JSON ABI metadata from `juliac` to generate C headers and Python ctypes bindings. Its sibling `JLWInterop` provides shared ABI types and supports trimmed libraries. Keep these build/ABI concerns outside the main runtime package. [JuliaLibWrapping repository](https://github.com/JuliaInterop/JuliaLibWrapping.jl)

Pin a tested Julia 1.13.x toolchain and compatible wrapping revision. Inspect its current shared-library examples and ABI-export syntax during implementation; generate the build command from that verified interface rather than guessing flags in this plan. Use `juliac`'s trimming diagnostics as a required check, with concrete Float32/Float64 entry points and all needed methods reachable from exports.

Proposed C ABI: version/model-info queries; binary mix; encode/decode; bulk RGB mixing. Use fixed-width scalars, pointers with explicit element counts, caller-owned outputs, and integer status returns (or the verified equivalent `JLWStatus`). Start with pointer-based output rather than relying on cross-language tuple/struct return conventions. Define RGB channel order, memory layout, aliasing, alignment, lifetimes, and zero-length behavior. Invalid sizes, null pointers, nonfinite values, or invalid weights return documented errors where detectable; no Julia exception may unwind into foreign code.

Avoid dynamic dispatch, runtime `eval`/`include`, lazy method generation, I/O, and allocations in ABI hot paths. Keep any loading and validation outside the compiled kernels. Preserve buffer ownership and GC roots wherever Julia-owned data backs pointers, and make shared tables read-only by API contract. Confirm concurrent calls are safe after any required initialization.

Generate and exercise the actual C header and Python package with JuliaLibWrapping. Test a clean consumer process with no Julia executable on PATH and no source-tree table paths, following any required runtime initialization contract. Record shipped runtime libraries, platform support, binary/data sizes, and startup behavior. PackageCompiler can be investigated as a fallback, but it does not satisfy the trimmed-library milestone by itself.

## 6. Validation and acceptance gates

Separate fast runtime tests from expensive numerical/precompute tests and full release validation.

| Area | Required evidence |
| --- | --- |
| Reference model | Pure-pigment results, scale invariance of concentrations, stable reflectance limits, independently checked integration and RGB conventions |
| Derivatives/solvers | Finite-difference gradient checks, positivity/simplex invariants, convergence/restart diagnostics, boundary-solution fixtures |
| LUT kernel | Synthetic affine tables reproduce analytic interpolation; all cube endpoints and simplex boundary cases stay in bounds |
| Algebra | Round-trip and same-color absolute error initially <= `2e-6` for Float32 and `1e-12` for Float64; exact explicit binary endpoints; reversal symmetry and weight-scale invariance within tolerance |
| Quantization | All stored inverse concentrations form a valid simplex; checksums and metadata round-trip; no NaN/Inf values |
| Model fidelity | Compare LUT and spectral mixing over pigment pairs, simplex faces, saturated/out-of-pigment-gamut RGB, near-black colors, random colors, and multi-color blends |
| Visual behavior | Blue/yellow green mixtures, magenta/yellow oranges, white-tint hue/chroma curves, and repeated-mixing examples compared to reference curves |
| Performance | Zero steady-state allocations in scalar and preallocated bulk kernels, throughput and latency with warm/cold caches, memory and artifact size |
| Packaging | Fresh consumer installation excludes Optim/ForwardDiff/wrapping tooling; no precompute or network requirement at runtime |
| Compiled ABI | Trim succeeds; C and generated Python clients match Julia across randomized inputs, invalid-input cases, and full-size table relocation |

Separate surrogate-fit error, inverse-solver error, table interpolation error, and byte-quantization error in reports. Provisional LUT-versus-spectral mixing targets are p99 encoded-sRGB channel error <= `2/255`, maximum <= `8/255`, and p99 Oklab Euclidean distance <= `0.01` on the fixed validation corpus. These are project targets, not paper guarantees; if they fail, improve precision/resolution or boundary interpolation and document the tradeoff. Round-trip tests alone cannot establish mixing quality because residuals cancel even poor tables.

Run deterministic small-grid regeneration in CI; reserve full-grid generation and exhaustive 8-bit round-trip checks for explicit release jobs. Test Julia 1.13 and subsequent supported stable minors; pin the compiler/wrapping combination for binary releases and expand the OS/architecture matrix only after smoke tests succeed.

## 7. Implementation order

1. **Scaffold:** create runtime/precompute/build/test workspace projects; select input-data sources; settle pigment order, color transfer convention, wavelength grid, and artifact schema.
2. **Prove the runtime and compiled boundary:** implement tiny-table interpolation, latents, residuals, and scalar/bulk kernels; compile and wrap them with JuliaLibWrapping; run C/Python smoke tests. Test full-size dummy payload embedding before expensive spectral work.
3. **Implement the spectral reference:** load validated data, evaluate K-M/Saunderson/colorimetry, and verify ForwardDiff gradients. Exit with checked reference fixtures.
4. **Fit surrogates and inverse solver:** implement the continuation fit and simplex-aware inverse solver, collect convergence/perceptual/gamut diagnostics, and measure solve cost.
5. **Generate development LUTs:** add resumable generation, quantization, boundary padding, runtime-format export, and independent quality reports. Refine choices until acceptance gates hold.
6. **Generate the production model:** create the 256-cubed table pair with reproducible metadata; validate quality, memory, load time, and throughput; package the default data.
7. **Release the Julia and compiled APIs:** rerun compilation and generated-binding tests with real assets, verify dependency isolation, document color/alpha/weight contracts, and publish regeneration instructions plus measured limitations.

The final implementation is complete when the ordinary Julia package and generated foreign-language bindings use the same validated table pair, runtime operations perform only lookup/interpolation and latent arithmetic, and every expensive modeling or optimization step remains in `precompute/`.
